# Spec 31: DB Redesign — Paperclip-Style Normalized Schema

> **Status:** DRAFT v1
> **Last updated:** 2026-04-24
> **Depends on:** Specs 23–30 (defines the entities this spec models)
> **Replaces:** [packages/db/src/tables.ts](../../packages/db/src/tables.ts), [packages/db/migrations/*](../../packages/db/migrations/) (hand-rolled SQL + custom runners)
> **Scope:** Assume everything specs 23–30 shipped. Design the schema as if greenfield, no legacy.

---

## What This Is

A full DB redesign modeled on paperclip's 73-table schema (`/tmp/paperclip-db/packages/db/src/schema/`). The current `company_states.snapshot_data` jsonb blob pattern blocks CAS, indexing, multi-node, event-log alignment, and cost queries. This spec throws it out and replaces it with one-file-per-table normalized schema that encodes business invariants as partial indexes, FK constraints, and composite B-trees.

Nothing about the data model changes. Everything about how it's stored changes.

---

## Principles (from paperclip)

1. **One file per table.** `packages/db/src/schema/<table>.ts`. No `tables.ts` conglomerate. PR-reviewable.
2. **UUID PKs generated by the database.** `uuid("id").primaryKey().defaultRandom()`. 16 bytes, gapless, unpredictable.
3. **Real FKs on every reference.** `references(() => parent.id)` with explicit `onDelete` behavior. Orphans illegal.
4. **Indexes declared with the table.** `(table) => ({ ... })` block. No "add index later."
5. **Composite indexes match query patterns.** Equality columns first, range columns last. `(company_id, status)` for `WHERE company_id = ? AND status = ?`.
6. **Partial indexes encode business invariants.** `uniqueIndex(...).where(sql\`...\`)` — "only one active claim per task" enforced by the DB, not app code.
7. **GIN trigram indexes for text search.** `using("gin", col.op("gin_trgm_ops"))` for fuzzy title/description search.
8. **No master "state" blob.** Every entity has its own table. "Snapshot" is a query.
9. **Telemetry as append-only tables.** `activity_log`, `cost_events`, `skill_usage_events` — separate from core entities, indexed for timeline queries.
10. **Drizzle-kit native migrations.** `drizzle.config.ts` + auto-generated `NNNN_codename.sql` files. No custom runners, no `001b_fix_schema`.
11. **Timestamps are `timestamptz`.** Never bare `timestamp`.
12. **Money is `integer` cents.** Never `float`, never `numeric` (for our precision).
13. **Status/kind/role columns use `text` with `CHECK` constraints.** Not postgres `enum` types — adding values to enums is painful. `CHECK (status IN (...))` is swappable via ALTER TABLE.
14. **Updated timestamps via trigger**, not app-enforced. One `set_updated_at()` function reused across tables.

## Core Tables — Detailed Schemas

Four tables matter most. Full schemas below. The other 26 follow the same style.

### 1. `companies`

```typescript
import { pgTable, uuid, text, integer, timestamp, uniqueIndex } from "drizzle-orm/pg-core";

export const companies = pgTable(
  "companies",
  {
    id: uuid("id").primaryKey().defaultRandom(),
    name: text("name").notNull(),
    slug: text("slug").notNull(),
    status: text("status").notNull().default("active"),         // active | paused | archived
    description: text("description"),
    goal: text("goal"),
    boardOwnerEmail: text("board_owner_email").notNull(),

    taskPrefix: text("task_prefix").notNull().default("ARC"),    // for ARC-42 style ids
    taskCounter: integer("task_counter").notNull().default(0),

    budgetMonthlyCents: integer("budget_monthly_cents").notNull().default(0),
    spentMonthlyCents: integer("spent_monthly_cents").notNull().default(0),
    budgetResetAt: timestamp("budget_reset_at", { withTimezone: true }),

    createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true }).notNull().defaultNow(),
  },
  (table) => ({
    slugUniqueIdx: uniqueIndex("companies_slug_idx").on(table.slug),
    taskPrefixUniqueIdx: uniqueIndex("companies_task_prefix_idx").on(table.taskPrefix),
    statusIdx: index("companies_status_idx").on(table.status),
  }),
);
```

**Decisions:**
- `slug` unique for URL routing
- `taskPrefix` + `taskCounter` give human-friendly task IDs (`ARC-42`)
- Budget fields here, not scattered across tables
- No `snapshot_data`. The "current state" of a company is `SELECT * FROM tasks WHERE company_id = ?` and 5 other tables.

### 2. `agents`

```typescript
export const agents = pgTable(
  "agents",
  {
    id: uuid("id").primaryKey().defaultRandom(),
    companyId: uuid("company_id").notNull().references(() => companies.id, { onDelete: "cascade" }),
    role: text("role").notNull(),                                // ceo | cto | pm | developer | tester | ui_designer | marketing | skills_lead
    displayName: text("display_name").notNull(),

    soulPromptRef: text("soul_prompt_ref").notNull(),            // path to role soul file

    isInternal: boolean("is_internal").notNull().default(false), // true for facilitator_agent etc.

    createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true }).notNull().defaultNow(),
  },
  (table) => ({
    companyRoleUniqueIdx: uniqueIndex("agents_company_role_idx").on(table.companyId, table.role),
    companyIsInternalIdx: index("agents_company_is_internal_idx").on(table.companyId, table.isInternal),
    roleCheck: sql`CHECK (role IN ('ceo','cto','pm','developer','tester','ui_designer','marketing','skills_lead') OR is_internal = true)`,
  }),
);
```

**Decisions:**
- Unique `(company_id, role)` — one agent per role per company
- OpenCode-only runtime — no adapter fields. Multi-runtime support (Claude Code, Codex, Cursor, Gemini) is a later addition via `ALTER TABLE ADD COLUMN adapter_type text NOT NULL DEFAULT 'opencode'` when we scale there.
- `is_internal` flag for facilitator/memory agents that aren't on the org chart
- CHECK constraint enforces valid role values

### 3. `tasks` — the big one

```typescript
export const tasks = pgTable(
  "tasks",
  {
    id: uuid("id").primaryKey().defaultRandom(),
    companyId: uuid("company_id").notNull().references(() => companies.id, { onDelete: "cascade" }),
    sprintId: uuid("sprint_id").references(() => sprints.id, { onDelete: "set null" }),
    parentTaskId: uuid("parent_task_id").references((): AnyPgColumn => tasks.id, { onDelete: "set null" }),

    taskNumber: integer("task_number").notNull(),                // e.g. 42 → ARC-42
    identifier: text("identifier").notNull(),                    // cached "ARC-42" for quick display

    title: text("title").notNull(),
    description: text("description"),
    kind: text("kind").notNull().default("standard"),            // standard | technical_plan | acceptance_spec | implementation | board_handoff | service_validation | skill_apply_proposal
    priority: text("priority").notNull().default("medium"),      // low | medium | high | critical

    status: text("status").notNull().default("planned"),         // planned | ready | claimed | in_progress | blocked | completed | verified | cancelled
    assignedRole: text("assigned_role"),
    assignedAgentId: uuid("assigned_agent_id").references(() => agents.id, { onDelete: "set null" }),

    // CAS columns — race-safe claim (paperclip pattern)
    checkoutRunId: uuid("checkout_run_id").references((): AnyPgColumn => heartbeatRuns.id, { onDelete: "set null" }),
    executionRunId: uuid("execution_run_id").references((): AnyPgColumn => heartbeatRuns.id, { onDelete: "set null" }),
    executionLockedAt: timestamp("execution_locked_at", { withTimezone: true }),

    dependsOnTaskIds: uuid("depends_on_task_ids").array().notNull().default(sql`ARRAY[]::uuid[]`),

    plan: jsonb("plan").$type<PlanStep[]>().notNull().default([]),
    evidence: jsonb("evidence").$type<Record<string, unknown>>(),
    feedback: text("feedback"),

    claimedAt: timestamp("claimed_at", { withTimezone: true }),
    startedAt: timestamp("started_at", { withTimezone: true }),
    completedAt: timestamp("completed_at", { withTimezone: true }),
    cancelledAt: timestamp("cancelled_at", { withTimezone: true }),

    createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true }).notNull().defaultNow(),
  },
  (table) => ({
    identifierUniqueIdx: uniqueIndex("tasks_identifier_idx").on(table.identifier),
    companyTaskNumberUniqueIdx: uniqueIndex("tasks_company_task_number_idx").on(table.companyId, table.taskNumber),

    // Core query patterns
    companyStatusIdx: index("tasks_company_status_idx").on(table.companyId, table.status),
    companyAssignedRoleStatusIdx: index("tasks_company_role_status_idx").on(table.companyId, table.assignedRole, table.status),
    companySprintStatusIdx: index("tasks_company_sprint_status_idx").on(table.companyId, table.sprintId, table.status),
    parentIdx: index("tasks_company_parent_idx").on(table.companyId, table.parentTaskId),

    // Text search
    titleSearchIdx: index("tasks_title_search_idx").using("gin", table.title.op("gin_trgm_ops")),

    // Business invariant: exactly one active claim per task
    activeClaimUniqueIdx: uniqueIndex("tasks_active_claim_idx")
      .on(table.id)
      .where(sql`${table.checkoutRunId} IS NOT NULL AND ${table.status} IN ('claimed','in_progress')`),

    // CHECK constraints
    statusCheck: sql`CHECK (status IN ('planned','ready','claimed','in_progress','blocked','completed','verified','cancelled'))`,
    priorityCheck: sql`CHECK (priority IN ('low','medium','high','critical'))`,
    kindCheck: sql`CHECK (kind IN ('standard','technical_plan','acceptance_spec','implementation','board_handoff','service_validation','skill_apply_proposal'))`,
  }),
);
```

**Decisions:**
- **CAS columns day one** — `checkoutRunId`, `executionRunId`, `executionLockedAt`. `task_claim` becomes a single SQL UPDATE with compound WHERE.
- **`identifier` cached** — `ARC-42` is stored, not computed. Unique across the entire DB for URL routing.
- **Partial unique index** enforcing "at most one active claim per task" — DB-level, not app-level.
- **Self-referential parent** for subtasks.
- **Arrays for `dependsOnTaskIds`** (Postgres native array of uuids) so we can `WHERE ? = ANY(depends_on_task_ids)`.
- **GIN trigram on title** for fuzzy search in the UI.
- **All status values enforced by CHECK.** Typos fail at write time.

### 4. `heartbeat_runs`

```typescript
export const heartbeatRuns = pgTable(
  "heartbeat_runs",
  {
    id: uuid("id").primaryKey().defaultRandom(),
    companyId: uuid("company_id").notNull().references(() => companies.id, { onDelete: "cascade" }),
    agentId: uuid("agent_id").notNull().references(() => agents.id, { onDelete: "cascade" }),

    beatNumber: integer("beat_number").notNull(),
    trigger: text("trigger").notNull(),                          // scheduled | mention | reconcile | manual
    triggerDetail: jsonb("trigger_detail").$type<Record<string, unknown>>(),

    status: text("status").notNull().default("running"),         // running | completed | failed | stranded
    cause: text("cause"),                                         // on failure: beat_hard_cap | prompt_failed | ...

    sessionId: text("session_id"),                                // OpenCode session id
    trustBand: text("trust_band").notNull().default("standard"), // snapshot at start

    // Verdict (spec 30 Chunk B)
    verdictScore: real("verdict_score"),                          // 0..1
    verdictOutcome: text("verdict_outcome"),                      // pass | fail
    verdictSignals: jsonb("verdict_signals").$type<VerdictSignals>(),

    // Telemetry
    totalTokens: bigint("total_tokens", { mode: "number" }).notNull().default(0),
    totalCostCents: integer("total_cost_cents").notNull().default(0),
    toolCallCount: integer("tool_call_count").notNull().default(0),

    // Process lifecycle
    processPid: integer("process_pid"),
    processStartedAt: timestamp("process_started_at", { withTimezone: true }),

    // Retry/recovery
    retryOfRunId: uuid("retry_of_run_id").references((): AnyPgColumn => heartbeatRuns.id, { onDelete: "set null" }),
    processLossRetryCount: integer("process_loss_retry_count").notNull().default(0),

    startedAt: timestamp("started_at", { withTimezone: true }).notNull().defaultNow(),
    finishedAt: timestamp("finished_at", { withTimezone: true }),
    createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
  },
  (table) => ({
    companyAgentStartedIdx: index("heartbeat_runs_company_agent_started_idx").on(table.companyId, table.agentId, table.startedAt),
    companyStatusIdx: index("heartbeat_runs_company_status_idx").on(table.companyId, table.status),
    companyBeatNumberIdx: index("heartbeat_runs_company_beat_number_idx").on(table.companyId, table.beatNumber),

    // Stranded-run reconciliation (spec 32)
    strandedIdx: index("heartbeat_runs_stranded_idx").on(table.status, table.startedAt).where(sql`status = 'running'`),

    statusCheck: sql`CHECK (status IN ('running','completed','failed','stranded'))`,
    verdictOutcomeCheck: sql`CHECK (verdict_outcome IN ('pass','fail') OR verdict_outcome IS NULL)`,
  }),
);
```

**Decisions:**
- One row per beat, keyed by `beat_number` within company
- Verdict (spec 30) embedded; `verdictSignals` jsonb for the composite
- Process PID + started_at enable stranded-run sweeper
- Partial index on `status='running'` makes stranded scan O(running count), not O(all runs)
- `retry_of_run_id` self-ref so retried beats keep lineage

## Triggers

One shared trigger for `updated_at`:

```sql
CREATE OR REPLACE FUNCTION set_updated_at() RETURNS trigger AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

Applied to every table with `updated_at`. One function, 20 `CREATE TRIGGER` statements in the initial migration.

## Migrations

### Tooling
- `packages/db/drizzle.config.ts` exactly like paperclip's: `schema: "./dist/schema/*.js"`, `out: "./src/migrations"`, `dialect: "postgresql"`.
- `package.json` scripts:
  ```json
  "db:generate": "drizzle-kit generate",
  "db:migrate": "drizzle-kit migrate",
  "db:studio": "drizzle-kit studio"
  ```
- Delete all `run-XXX.ts` scripts and `001b_fix_schema.sql`.

### Migration strategy
This is a full rewrite. Options:

**Option A — Clean slate (recommended).** Drop the existing DB, apply new migrations, re-seed companies. Only viable if data is dev-only today. Fast, clean, no migration pain.

**Option B — Dual-write transitional.** Keep old tables, create new tables in parallel, dual-write for a week, verify counts match, flip reads, drop old tables. Complicated. Skip unless you have real production data.

**Recommended:** Option A. A one-time data audit shows what to preserve (if anything) and we rebuild. Seed a canonical test company via a seed script.

## Key Query Patterns Enabled

| Query | Old (blob) | New |
|---|---|---|
| "Tasks assigned to developer, in progress" | Parse entire snapshot jsonb per company | `WHERE company_id = ? AND assigned_role = 'developer' AND status = 'in_progress'` — index hit |
| "Claim task atomically" | Impossible on in-memory cache | `UPDATE tasks SET checkout_run_id = ?, status = 'in_progress' WHERE id = ? AND status IN (...) AND checkout_run_id IS NULL` |
| "All artifacts for task X" | Walk snapshot | `WHERE task_id = ?` — FK index |
| "Sprint spend breakdown by provider" | Not possible | `SELECT provider, SUM(cost_cents) FROM cost_events WHERE company_id = ? AND occurred_at BETWEEN ? AND ? GROUP BY provider` |
| "Skill EMA over last 50 invocations" | Full skill_artifacts row read | `SELECT outcome_score FROM skill_usage_events WHERE skill_id = ? ORDER BY occurred_at DESC LIMIT 50` |
| "Stranded beats older than 30 min" | No way to detect | `SELECT id FROM heartbeat_runs WHERE status = 'running' AND started_at < now() - interval '30 min'` — partial index hit |
| "Fuzzy search task titles" | Not possible | `WHERE title % 'login form'` with trigram GIN index |
| "Role trust timeline for developer" | Not persisted | `SELECT * FROM role_trust_events WHERE company_id = ? AND role = 'developer' ORDER BY created_at DESC` |

## Performance Characteristics

At scale of 1000 companies × 1000 tasks × 100 beats/day:

| Table | Row count (year 1) | Partitioning? |
|---|---|---|
| `tasks` | 1M | No — indexed |
| `artifacts` | 5M | No — indexed |
| `heartbeat_runs` | 36M | Yes — monthly partition by `started_at` |
| `activity_log` | 500M | Yes — monthly partition, drop > 6 months |
| `cost_events` | 100M | Yes — monthly partition by `occurred_at` |
| `skill_usage_events` | 50M | Yes — monthly partition |
| `memory_units` | 10M | No (pgvector has its own retention) |
| `memory_embeddings` | 10M | No (pgvector index) |

Monthly partitioning via `PARTITION BY RANGE (created_at)` + automated partition creation is a follow-up, not blocking for v1.

## Indexes Audit (anti-pattern detection query, should return zero unindexed FKs)

```sql
SELECT conrelid::regclass AS table_name, a.attname AS column_name
FROM pg_constraint c
JOIN pg_attribute a ON a.attrelid = c.conrelid AND a.attnum = ANY(c.conkey)
WHERE c.contype = 'f'
  AND NOT EXISTS (
    SELECT 1 FROM pg_index i
    WHERE i.indrelid = c.conrelid AND a.attnum = ANY(i.indkey)
  );
```

Every FK declared in this spec has a supporting index. This query should return zero rows after migration.

## Acceptance Criteria

1. All 30 tables exist as separate files under `packages/db/src/schema/`.
2. `packages/db/src/tables.ts` is deleted. Legacy dual-schema pattern (`arceusSchema ? ... : pgTable(...)`) is gone.
3. All migrations generated by `drizzle-kit generate` — no hand-written SQL except for triggers and any `CREATE EXTENSION` (pgvector, pg_trgm).
4. `drizzle.config.ts` matches paperclip's shape.
5. Every FK has a supporting index (the audit query above returns zero rows).
6. Every `status`, `kind`, `role`, `priority`, `severity`, `band` column has a `CHECK` constraint.
7. `tasks` table has CAS columns (`checkout_run_id`, `execution_run_id`, `execution_locked_at`) and a partial unique index enforcing at-most-one-active-claim.
8. `heartbeat_runs` has a partial index on `status='running'` for stranded-run detection.
9. `skill_evolve_jobs` has a partial index on `status='pending'` for worker lease.
10. No in-memory snapshot blob exists. `company_states` table is deleted. `getSnapshot()` in app code is replaced by targeted queries per consumer.
11. `idempotency_keys` table exists and is used by every MCP mutation.
12. Every table has `created_at` (and `updated_at` where mutable) as `timestamptz`.
13. All text-search fields (task title, task description, skill name) have trigram GIN indexes.
14. Seed script produces a canonical test company with all 30 tables populated.
